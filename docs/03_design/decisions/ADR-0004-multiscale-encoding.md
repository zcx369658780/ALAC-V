# ADR-0004：多尺度编码采用"逐级独立 518 前向"

## 背景

DINOv2 的位置编码与 patch 网格绑定在固定输入尺寸（ViT-S/14，常用 518 → 37×37 patch）。多尺度表示有四档（1/1、1/2、1/4、1/8），但模型不能接受"四种分辨率同时输入"。

## 决策

- 每个尺度图像**等比缩放 + 中心裁剪**到 518×518，各自独立前向，得到 4 组 CLS + patch。
- patch 网格在所有尺度上保持 37×37，使"同一 (i,j) patch"跨尺度可对齐，便于后续跨尺度注意力/记忆实验。
- 多尺度描述子 = 4 个 L2 归一化 CLS 的**拼接后再归一化**（1536 维）。等权，不学习权重。
- 插值固定为 bicubic（`antialias=True`），只对缩放；不做锐化、不做超分。

## 理由

- 独立前向是唯一能保持 patch 网格语义一致的方式；拼接通道会破坏预训练统计（DINOv2 输入是 3 通道 RGB）。
- 拼接 CLS 简单、无需训练、可解释：每一维可追溯到具体尺度。
- 计算成本线性：4 级 ≈ 4× 单级，便于在实验中直接核算。

## 后果

- **正面**：多尺度是"可枚举、可消融"的（去掉任一级即可测贡献）；BN 无关，batch=1 稳定。
- **负面**：对 1/8 尺度图放大回 518 并不恢复细节，它编码的是**低频/全局结构**，不是"更多信息"。报告中必须如此表述，不得把"多尺度"说成"超分辨率"。
- **负面**：4 次前向 ≈ 4 倍算力；若单图超时，优先降到 2 级（L0+L2）而不是改模型。

## 备选与否决

- 金字塔特征图（FPN 式）在 CNN 上可行，但 ViT 无原生多尺度特征图，需改结构 → 超出"不训练主干"的边界。否决。
- 把不同尺度拼成 batch 一起前向：等价实现，仅影响吞吐，不影响数值；实现上按 batch 分组以提升 GPU 利用率。
