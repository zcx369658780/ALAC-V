# ADR-0006：特征 FP16 落盘、FP32 检索

## 背景

任务单要求"保存 FP16 特征"。但 FP16 直接做点积会引入累积误差，且不同硬件半精度累加策略不同，影响可复现性。

## 决策

- **存储**：`cls`、`patch` 均 `float16`，SafeTensors，附 `meta_json`。
- **检索**：读入后 `astype(np.float32)` → L2 归一 → 余弦（矩阵乘）。
- **描述子**：
  - 单源：`v = cls / ||cls||`；
  - 多源：`v = concat([cls_s / ||cls_s||]) `，再整体归一化；各源**等权**。
  - 不使用 patch 做全局检索（patch 用于局部匹配/回溯，见 `retrieval.py::roi_match`）。
- **数值校验**：单测中比较 FP16 与 FP32 前向得到的余弦，要求 |Δcos| < 2e-3；报告里给出实测值。

## 理由

- 存储省一半（1.05 MB → 526 KB/patch 张量），符合"高效编码"目标；
- FP32 累加使检索在 CPU/GPU 上结果一致，可复现；
- 等权拼接不需要训练任何权重，符合"不训练主干/不引入额外学习"的边界。

## 后果

- **正面**：特征文件小、读取快、跨平台一致。
- **负面**：等权拼接假设各尺度同等重要，可能次优 → 实验中将"仅 L0"、"L0+L2"、"全 4 级"作为消融，直接测出来；不靠猜。
- **负面**：FP16 极小值（<6e-8）会下溢为 0，但 CLS 经 LayerNorm 后量级 ~O(1)，实测无影响（报告给出 min/median/max 绝对误差）。
