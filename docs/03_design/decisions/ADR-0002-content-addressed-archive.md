# ADR-0002：原始图像内容寻址归档 + 只读保护

## 背景

任务单要求：原始文件只读保存、记录 SHA-256、不允许不可逆覆盖。同时需要支持重名文件（不同目录同名）、重复文件（同内容不同名）。

## 决策

1. 归档路径 = `data/raw/<sha256[0:2]>/<sha256><.ext>`，即**内容寻址**。同内容不同名 → 同一归档文件，`source_name` 记入数据库。
2. 写入流程：临时文件 → 计算 SHA-256 → 原子 rename → 设置只读属性（Windows `FileAttributes.ReadOnly`，并移除 `Write` ACL 不必要；仅属性位足够防误写）。
3. 归档前必须**完整解码**一次（`Image.open` + `load()`），解码失败的文件不归档、记 `rejected`。
4. 扩展名取实际解码格式（`image.format`），不信任输入文件名。
5. 重复入库直接返回已有 `image_id`（幂等），不重复拷贝。

## 理由

- 内容寻址天然去重，SHA-256 即完整性证明；
- 文件名不再承担身份，避免编码/空格/大小写问题；
- 只读属性位成本低，能拦截绝大多数误写脚本。

## 后果

- **正面**：`data/raw` 可被任意复制/校验；数据集清单即 SHA-256 列表。
- **负面**：Windows 的只读属性可被同用户移除，不是安全边界，只是防误操作。**真正的保证是代码层面不提供删除/覆盖接口**，并有 `verify_raw_integrity` 校验。
- **负面**：EXIF 中的原始文件名可能含个人信息，`source_name` 仅存文件名不含路径。

## 备选与否决

- 按原始文件名归档：重名冲突，且文件名不可信。否决。
- 归档到数据库 BLOB：SQLite 体积膨胀、备份困难、无法用系统工具核对。否决。
